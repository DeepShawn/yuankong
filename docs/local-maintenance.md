# Windows 本机维护

在完整 Windows 接收端文件夹中，右键 **本机维护.cmd → 以管理员身份运行**。
此入口会打开一个独立、可见的维护窗口，先说明操作并请求本机确认，然后停止属于当前安装的接收端。
手机连接随之断开。工具等待恢复工作进程退出；仍有启动面板、录制等进程占用目录时，先关闭它们再重试。

维护菜单提供：

1. **文件夹改名**：只更改同一父目录内的文件夹名称，不覆盖已有目录。完成后更新精确匹配当前安装的当前用户自启动项；其他安装的自启动项保留。可在本机再次确认后打开新目录的可见 `Start.exe` 启动面板。失败时尝试恢复原名称和原自启动项。
2. **卸载**：只移除发布清单中校验通过的程序文件及属于当前安装的当前用户自启动项。用户上传的文件、升级 ZIP、其他未知文件和 `%APPDATA%\LanCmd` 中的配置、日志、恢复备份保留。程序文件先复制到本机维护目录并校验，再从安装目录移除；失败时尝试回退。
3. **批量修改普通文档日期**：通过 Windows 文件选择器选择 1–100 个文档，输入电脑当地时间 `YYYY-MM-DD HH:MM:SS`，在本机确认后修改最后修改时间。支持 TXT、Markdown、CSV、PDF、Office 和 OpenDocument 文档；不修改创建时间或内容。接收端、系统目录、应用目录、配置／恢复目录、可执行文件和脚本不属于此功能范围。文件系统不能精确保存所选日期时，报告失败并尝试恢复原日期，不把取整后的结果算作成功。
4. **恢复文档原日期**：选择本机维护目录中的 `dates-<编号>.json`。只有文件身份、大小和当前日期与记录相符时才恢复；后来编辑或替换过的文件会跳过，结果写回原记录。

日期编辑也要先停止接收端，不能由手机后台执行。工具不接受自动确认、远程操作或无人值守参数。

## 维护前的恢复检查

存在应用锁、文件锁、USB 断开、设备策略或文件任务暂存恢复记录时，工具会阻止改名和卸载。请先在原接收端恢复相关限制，并移除已解锁记录；文件任务暂存可先重新启动接收端、打开文件任务列表完成检查和清理。即使权限已经恢复，尚未清理的锁记录仍须处理，以免误删仍有用的恢复能力。

升级尚未完成或恢复记录损坏时，也会阻止维护。不要为绕过检查直接删除记录；保留它们并先解决异常。

摄像头、麦克风、网卡等持久设备状态，以及热点、壁纸和防火墙设置，须先在 Windows 本机检查并按需恢复。工具不自动更改这些设置，不删除别的软件创建的规则。改名后，路径绑定的快捷方式、任务和手动设置的防火墙规则可能需要由电脑管理员更新。

## 日志与故障回退

每次维护在 `%LOCALAPPDATA%\LanCmdMaintenance\session-<编号>` 保留可见记录：

- `maintenance.jsonl`：操作及失败记录。
- `installation.json`：原路径、新路径、自启动项和卸载进度。
- `removed-files`：卸载前校验过的程序副本。
- `dates-<编号>.json`：文档身份、原日期、目标日期和逐项结果。
- `python` 和 `local_maintenance.py`：独立维护运行时，以免原目录占用影响维护。

若突然断电，自动回退可能来不及完成。关闭接收端和维护窗口后，先查看 `installation.json`：改名可将记录中的目标目录手动改回原名；卸载可将 `removed-files` 的内容复制回原位置，遇到已有文件先比较，不要直接覆盖新文件。自启动项在记录中保留原值，必要时由本机管理员恢复。

维护目录、配置、日志和恢复备份不会自动清理。确认所有恢复事项处理完毕且不再需要副本后，才由电脑使用者自行删除。
