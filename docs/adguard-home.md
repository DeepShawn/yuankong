# AdGuard Home 启动联动与手机管理入口

本功能接入**已在电脑安装和配置的 AdGuard Home Windows 服务**，不捆绑或下载 AdGuard Home，不代替其安装向导，也不自动开启访问记录。AdGuard Home 是独立软件，官方安装方法见 [Getting Started](https://github.com/AdguardTeam/AdGuardHome/wiki/Getting-Started)。请在本机完成安装、设置独立管理密码和 HTTPS 证书，并告知受控设备的使用者。

## 在电脑启用一次

1. 完成 AdGuard Home 的官方 Windows 服务安装和 DNS／HTTPS 配置，确认可通过其管理页正常访问。服务名应为 `AdGuardHome`，程序应为本地普通文件 `AdGuardHome.exe`。
2. 右键以管理员身份运行包内 `AdGuardSetup.cmd`。选择 `1`，核对服务程序路径与 SHA-256，输入 `ENABLE` 确认启动联动。
3. 选择 `3` 可以立即按已确认的设置启动，或之后使用 `start.bat`。

启用记录保存在 `HKLM\SOFTWARE\LocalNetworkGuardian` 的 `AdGuardHomeOptIn`，不存储 DNS 管理密码或访问记录。服务程序或服务命令发生变化后，须重新在电脑确认，避免更新后自动启动未经确认的程序。

## 正常后台运行

`start.bat` 在接收端首次启动成功、检测到已在运行，以及更新后重启的路径中检查联动。未启用时不会操作服务；已在运行或启动中时不重复启动。已停止且授权匹配时，只通过 Windows 服务管理器发送启动请求，不额外弹窗或通知，不隐藏、改名或重装服务。

联动不更改 AdGuard Home 自身的 Windows 启动类型、DNS、ICS、网卡、防火墙或访问记录设置。Windows 服务本身的管理界面和系统日志正常保留。`start.bat` 原有控制台和正常路径的暂停行为不变，更新启动路径仍保留接收端退出码并自动退出。联动失败只记录在 `%APPDATA%\LanCmd\adguard-service.log`，不会使接收端启动失败。

启动服务需要 Windows 允许的权限；不足时不自动提权或弹 UAC，请在本机用管理员权限启动。不会自动恢复用户暂停或正在停止的服务。

在 `AdGuardSetup.cmd` 可以查看实时服务状态、选择 `2` 取消联动，或选择 `4` 并输入 `STOP` 停止服务。取消联动只取消本功能的启动请求；若服务原来由 Windows 自动启动，需在 Windows 服务管理器自行调整其启动类型。停止 DNS 服务可能影响已连接设备。

## 安卓入口

进入“网络与蓝牙”，完成管理验证后，展开“AdGuard Home 网站守护”，填写这台电脑的 **HTTPS 管理地址**，点击“打开独立 HTTPS 管理页”。手机浏览器直接连接并登录 AdGuard Home，LanCmd 不代理其请求、不接收管理密码或访问记录，也不保存浏览器登录信息。

只保存按电脑区分的管理地址。地址不能含用户名、密码、查询参数或片段，不支持 HTTP、跳过证书验证或降级。证书应受手机浏览器信任，电脑名称和证书应匹配。打开后可正常返回安卓管理页，原连接不因跳转而主动关闭。

设备分组、域名请求时间、查询记录与网站／服务规则，在 AdGuard Home 管理页中按其实际版本配置；它们不是 LanCmd 新增的采集接口或重新设计的管理 UI。

## DNS 范围与热点限制

- 本机及热点设备必须实际使用受控 DNS。仅启动服务不会改变它们的 DNS 设置。
- 若热点网关代理了所有查询，记录中可能只显示网关，不能准确区分每台设备。区分设备需要设备直接查询可达的 AdGuard Home 监听地址。
- Windows ICS 可能占用热点地址的 DNS 53 端口，须先解决监听冲突；本联动不会强制停用 ICS 或修改系统网络服务来抢占端口。
- 域名请求不等于实际打开网页；HTTPS 内容、具体 URL 路径和手机实际应用身份无法据此确认。加密 DNS、VPN、代理、缓存或直接 IP 可能绕过限制。
- 不提供抓包、通信解密、隐蔽记录或 Windows 本机按进程的防火墙规则。3.18.7 的本机确认 hosts 工具继续独立使用。
