# 3.18.3 — 前缀不动，只有白色正文跑马灯

前三版把「消息提醒：」和正文当成一整行一起滚，这是错的。正确行为是两块分开：

- **蓝色前缀（喇叭 + 「消息提醒：」）固定不动**，永远停在左侧；
- **只有白色正文滚动**：从屏幕最右端进入 → 匀速左移 → 被前缀挡掉消失 →
  同一条再从最右端重新出现。多条消息就是依次各跑一遍，最后一条之后回到第一条。

## 一、这次改了什么

| 项目 | 3.18.2（错） | 3.18.3 |
|---|---|---|
| 前缀 | 跟着正文一起滚 | 固定不动，单独一列 |
| 正文起点 | 左对齐（t=0 就能读全） | 轨道最右端（屏幕右侧） |
| 正文终点 | 滚到最后停住等间隔 | 越过前缀消失，立刻回到右端 |
| 停顿 | 3 个字宽 | 无停顿 |
| 轮巡 | 每条从左对齐开始 | 每条从右端横穿一遍 |

轨道（viewport）从前缀右边缘一直延伸到屏幕右侧留白内，正文在这条轨道里滚动；
`clip` 只作用在轨道上，所以文字越过前缀时被自然裁掉，看起来就是“从最左边消失”。

## 二、节奏

- 速度：2.4 个字号宽／秒（1080p ≈ 134 px/s）。
- 每条时长 = `(轨道宽 + 正文估算宽 × 1.05) / 速度`，也就是“从右端进入到完全越过左端”。
  1080p 上一条 20 字的消息约 13.6 秒横穿一次。
- 没有额外停顿：一条走完，下一条立刻从右边进来；只有一条时就是它自己不断循环。
- 排期仍用两端共享的字宽估算，所以手机预览和电脑的切换时刻一致。

## 三、两端一致

`windows/announcement_seewo.py` 与 `AnnouncementSeewo.kt` 依旧共用一张表，
这次新增 `prefix`（固定列）与 `viewport`（滚动轨道）两个盒子，两边都按
`advance()` 估算前缀宽度，所以轨道的起点在手机和电脑上是同一个像素。

`tools/render_announcement_preview.py` 可以直接出四帧对照图验证：
前缀四帧不动，正文四帧依次右进、左移、被裁。

## 兼容性

- 双端 3.18.3，Android versionCode 65，保留原签名与 miuix／KernelSU 外观。
- `config` 结构不变（`style` / `messages` / `prefix` / `duration` / `repeats` 语义同 3.18.2）。
- 经典样式不受影响。

## 已知边界

- 参考图只拍到一条短消息（正好静止在左侧），没有拍到滚动中的画面；
  滚动方向、速度与循环方式是按你描述的“从最右端进入、最左端消失、再从最右端出现”实现的。
- 正文完全越过前缀后到重新出现之前，轨道里是空的（这是 marquee 的正常空档）。
  想让空档更长/更短，调整 `SPEED_EM` 或 `durations()` 里的 `WIDTH_SLACK`。
