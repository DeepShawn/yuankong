# 3.18.2 — 跑马灯真的在跑：持续滚动 + 多消息轮巡

3.18.1 把外观校准对了，但行为做错了：我让短消息静止不动，而且只能显示一条。
实际的一体机通知是一条**跑马灯**——文字一直在动，多条消息轮着播。

## 一、现在的行为

- **始终滚动**：任何长度的消息都向左匀速移动，短消息也滚，不再有“静止左对齐”。
- **同一条里滚完就停**：文字从左边对齐开始，向左移动到完全移出视口，停一个间隔
  （3 个字号宽，1080p 约 1.3 秒），然后换下一条。
- **多条轮巡**：`messages` 里逐条播放，最后一条播完回到第一条，无限循环。
  每条都带自己的蓝色「消息提醒：」前缀。
- **只有一条时**：就是它自己循环。
- 每条时长 = `max(4 秒, (估算行宽 × 1.05 + 间隔) / 速度)`，速度仍是 2.4 个字号宽／秒。

为什么先左对齐再滚、而不是像网页 marquee 那样从右边缘进场：一体机的通知要在下达后
**立刻能读**。从左对齐开始，学生当场就能看到全文；从右进场则要先等 4 秒视口被填满。
两条路径的行程都算进时长里，所以节奏是连续的。

时长用的是**估算宽度**（`advance()`：CJK 1 em、拉丁 0.55 em），不是各端字体的真实
度量——这样手机和电脑的轮播时刻表严格一致，不会出现手机已经第 3 条、电脑还停在第 2 条。
1.05 的余量吸收真实字形略宽于估算的情况，避免切字。

## 二、手机端

- 希沃样式下「公告内容」变成**每行一条**，逐条轮巡，页面下方实时显示轮巡顺序
  （`1. … → 2. … → 3. …`）。
- 打开「希沃样式」时，原来的多行内容会自动拆成多条，不会丢。
- 点「播放预览」看到的就是完整的轮播时序（预览按单调时钟推进，暂停不计时）。
- 上限：30 条 × 500 字。第一条同时写进 `text`，旧接收端（不认识 `messages`）仍能显示。

## 三、兼容

- 双端 3.18.2，Android versionCode 64，保留原签名与 miuix／KernelSU 外观。
- `config` 新增 `messages: string[]`；为空时退回 `text`（单条），行为与 3.18.1 相同。
- `repeats` 现在按**轮**计：所有消息各播一遍算一轮。
- 经典样式完全不受影响。

## 四、字体宽度与观感的取舍

估算表是两端唯一的时刻表来源；滚动位移仍按各端真实测量的行宽推进。所以：
- 轮播切换点：两端完全一致；
- 位移速度：两端都是 130 px/s（1080p），但“滚完”的时刻按估算判定，
  真实字形宽 2–3% 时最多早/晚 0.2 秒，肉眼是“正好滚出”。

## 已知边界

- 极短消息（如「集合」）实际位移很短，主要时间是 4 秒下限的停留；
  想更长可以在 `announcement_seewo.py` 调 `MIN_SECONDS`。
- 参考图只拍到一条消息，多条的节奏是按一体机常见观感定的（滚动 + 停顿 + 下一条）。
  如果你们的机器是“从右边缘进场”，把 `offset()` 的起点改成 `viewport` 即可。
