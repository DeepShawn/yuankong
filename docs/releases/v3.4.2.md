# LanCmd 3.4.2

修复本地 Windows ZIP 更新的退出、替换和重启流程。

- `upgrade` 中的完整 ZIP 先校验路径、清单、版本和全部文件 SHA256，校验失败保留当前接收端。
- 校验通过后断开当前连接，释放远程共享、拖动、本机输入暂停与系统指针，再退出旧接收端。
- 独立更新进程等待旧进程真正退出后才解压，将新包内容替换到原安装目录，保留用户文件、升级 ZIP 和回退备份。
- 暂存和备份放在安装目录的 `.upgrade/run-...`，与安装文件同盘，修复安装在 D 盘／U 盘而 APPDATA 位于 C 盘时的跨盘替换失败。状态仍写入 `%APPDATA%\LanCmd\upgrade`。
- 更新实际运行 `start.bat --upgrade`。这一分支不执行 `pause`，CMD 隐藏运行并在启动完成后退出，不留下命令窗口，也不关闭其他 CMD 窗口。
- 根据本次任务编号、启动回执、进程创建时间及路径确认新版启动和 CMD 退出；启动失败先结束本次新进程，再恢复旧文件并验证旧版启动，保留错误和备份路径。
- 安卓自动等待同一电脑重新连接并显示本次更新结果；页面重建可继续等待，连接到其他电脑时停止跟踪，旧更新报告不会误报本次成功。

正在写入的文件任务、录制、脚本和延迟命令仍须先完成或取消。仍只使用手动放入本机的 ZIP，不增加在线下载更新，也不自动触发 UAC。

Android versionCode 42，继续使用既有签名，主题和功能保持 3.4.1 的选择。

正在运行的旧版更新程序仍使用旧代码。若 3.4.1 已因跨盘替换失败而无法自行更新，需要先手动解压完整 3.4.2 包覆盖并重新启动一次，后续更新才能使用修复后的流程。
