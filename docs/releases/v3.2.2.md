LanCmd 3.2.2 优化向 U 盘生成占位文件时的响应，允许小幅速度让步，继续优先快速预分配真实磁盘空间。

同时修复“在当前窗口下方打开”后新应用再次抢到前台的问题：启动维护期从 3 秒延长至最多 30 秒，识别慢启动窗口、所选程序的新窗口及已激活的复用窗口，并撤销目标窗口的置顶状态。复用窗口通过关联程序或 WPS 的完整可执行路径确认，不按同名程序粗略匹配。用户主动选择其他窗口、原窗口关闭或最小化时停止维护，后续打开请求也会取消旧维护。

此方式仍受 Windows 前台切换限制和应用行为影响；同一窗口内复用标签页、更晚的主动激活等情况无法保证。不会隐藏窗口或更改系统全局焦点策略。

- 新增“稳定／快速”模式，默认稳定。稳定预分配从 4 MiB 起步、最大批次 32 MiB，批次间短暂让行；快速模式从 8 MiB 起步、最大 256 MiB，两者都按磁盘耗时自动缩小或扩大批次。每批设置相应文件长度，避免旧实现最多 16 GiB 的单次分配及最后一次大范围长度更新。
- 路径与容量检查在后台进行，文件提交不再持有任务登记锁。USB 响应慢时，任务查询和取消请求仍可返回；无法识别目录、空间不足等结果显示在任务中。
- 后台工作线程使用 Windows 后台 I/O 优先级，让前台操作获得优先机会。快速预分配不按整个文件的逻辑大小硬性限速；仅在文件系统不支持时回退实际写入。稳定模式回退写入约 64 MiB/s 上限、8 MiB 短时突发，每 16 MiB 刷新；快速模式回退写入不固定限速，每 64 MiB 刷新。慢盘实际速度可能更低。
- 安卓区分检查、分配、写入缓存刷新、提交、取消中和清理中。当前磁盘调用返回且清理结束后才显示“已取消并清理”，提交完成阶段不再接收取消。

保留 0–500 GB、实际占用、非稀疏/非压缩、隐藏+系统属性、至少 1 GB 余量、不覆盖及异常退出清理。没有使用 SetFileValidData。

Windows 驱动或 USB 控制器自身停滞时，应用不能保证立即中止当前系统调用，也不能保证电脑绝不会卡顿。未做实体 U 盘大容量性能实测，实际速度与取消等待仍受设备、文件系统及碎片影响。
