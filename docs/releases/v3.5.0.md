# LanCmd 3.5.0

文件强制删除与启动、热点设置。

## 强制删除

- 文件菜单「删除 → 强制删除」及多选批量入口；文件夹继续使用普通删除。
- 先尝试 Windows 按句柄删除。可共享删除的占用句柄仍能保留，磁盘数据在最后一个句柄关闭后释放。
- 被独占时，通过 Restart Manager 查询真实占用应用。手机显示应用名、路径和进程启动时间，再次确认后结束所列应用并删除。应用未保存内容可能丢失；程序也可能重新创建同名文件。
- 文件身份变化、占用进程创建时间／路径变化或新增占用者时不会据旧确认操作新对象。系统服务、关键进程、其他登录会话及接收端受到保护。
- 支持 0–86400 秒延迟、取消后续步骤及顶部逐项结果；确认结束占用者不再次延迟。下次打开文件任务可继续处理待确认任务。不会关闭任意其他进程的文件句柄、修改 ACL、伪造崩溃提示或擅自安排重启。旧系统只能标记待句柄释放时会明确显示，不能当作已立即删除。

## 启动与网络

- 首页「系统 → 启动与网络」设置当前用户登录后启动本目录接收端、启动后自动开启 Windows 移动热点、自动放行接收端端口。
- 开关保存在接收端目录的 `startup-network.json`。自启使用正常的当前用户 Run 项；热点沿用 Windows 设置中的名称、密码，使用公开的移动热点 API，不返回热点密码。
- 热点启动与状态读取在后台运行，不阻塞文件管理或连接；仅在 Windows 确认 `On` 后显示已开启。实际可用性取决于系统版本、无线网卡、网络连接和系统策略。
- 防火墙规则仅针对本目录 Python 接收端程序、实际 TCP/UDP 端口和 `LocalSubnet` 来源。需要管理员接收端；保持防火墙开启，不自动提权或弹出 UAC。
- C 盘重启还原时，须将完整接收端目录放到保留盘，并在还原工具允许的维护模式／基线或保留策略中保存 Windows 自启项及热点配置。仅将目录放在 D 盘不能保证开机触发，本版本不会绕过还原卡或保护策略。具体配置仍需按所用还原工具完成。

Android versionCode 44，继续使用既有签名、miuix 构建与界面风格选择。Windows 必须完整覆盖新包并重新启动才支持新命令。
