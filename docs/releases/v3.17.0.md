# 3.17.0 — 应用快捷控制、接收端自我维护与公网联机

3.17.0 把三件平时要在电脑前做的事搬到手机上：控制正在运行的希沃白板／WPS／QQ，
维护接收端自己的安装目录与文件日期，以及在不在同一局域网时通过 frp 连回来。
三项都需要完整更新 Windows 包（新增四个 .py 模块）并重启接收端。

## 一、应用快捷控制（`app_control`）

首页「共享与控制 → 应用快捷控制」。

- **预设动作**：希沃白板、WPS Office、QQ 按进程名自动识别，提供翻页、首末页、
  画笔／橡皮／荧光笔／选择／黑板、保存、撤销、加粗、查找、开始／退出放映等按钮。
  每个动作就是一组按键，默认值写在 `app_control.py` 的 `PROFILES` 里。
- **两种发送方式**：
  - 后台（默认）：`PostMessage` 投递 `WM_KEYDOWN/UP`，不抢焦点，不打断电脑前的操作；
  - 前台执行：先把目标窗口切到前台再用 `SendInput`，适用于后台窗口不响应按键的程序。
    切换前台失败时返回提示，请先在远程画面点一下目标窗口。
- **发送消息**：把文字写入剪贴板、切到前台、`Ctrl+V` 粘贴，可选回车发送；
  结束后尽量还原电脑原来的剪贴板内容。适用于 QQ／微信等聊天窗口。
- **自定义按键**：对话框里直接发 `CTRL+S`、`PAGEDOWN` 一类的组合，不依赖预设。
- **窗口隐形**：把选定窗口 `ShowWindow(SW_HIDE)`。电脑桌面和任务栏看不到它，
  进程继续运行、内存与网络连接保留，手机端仍在列表里并可继续发按键；
  「恢复显示」把它放回前台，接收端停止或升级时也会自动恢复。
  最多同时隐藏 64 个窗口，记录写入 `%APPDATA%\LanCmd\app-control-hidden.json`；
  接收端异常退出后重启时会按句柄与 PID 核对并自动恢复，程序已退出或句柄被复用的记录直接丢弃。
- 绑定自定义快捷键：编辑 `%APPDATA%\LanCmd\app-control.json`，
  形如 `{"keys": {"seewo": {"pen": "CTRL+P"}}}`。手机端每次读取都会合并这份覆盖表。

> 预设快捷键来自各程序常见版本的默认键位，不同版本可能不同；失效时在电脑上确认实际
> 快捷键后用「自定义按键」或覆盖表修改。本功能不注入 DLL、不修改目标程序文件。

## 二、接收端自我维护（`self_manage`）

首页「系统与应用 → 自我维护」。三项操作都在电脑上由独立助手完成，
因为 Windows 不允许改名或删除仍在被解释器占用的安装目录。

### 1. 安装文件夹改名并重启

1. 手机提交新名称（同一父目录内、非 Windows 保留名、目标不能已存在）；
2. 接收端先把计划写进 `%LOCALAPPDATA%\LanCmdMaintenance\plan-*.json`，再回包；
3. 1.2 秒后本进程退出（`os._exit`），助手等待进程结束，结束本目录里的其他进程
   （`Start.exe` 面板、旧的接收端等），然后 `rename` 目录；
4. 若当前用户自启动项指向本目录，改写成新路径；其他安装的自启动项不动；
5. 默认从新路径重新启动（优先 `LanCmdAgent.exe`，其次包内 `pythonw`），
   手机约十秒后重连即可。

每一步都追加到 `remote-*.jsonl`；失败时助手停止并留下原因，不会半改名就跑。

### 2. 自我删除

- 结束本进程 → 删除当前用户自启动项（仅当值属于本目录）→ 递归删除安装目录；
- `keep_config=true` 时保留 `%APPDATA%\LanCmd`（配置、日志、日期与改名记录）；
- 需要手机端输入 `DELETE` 作为确认字符串，删除后无法从手机恢复，
  须重新解压发布包；
- 删除不可撤销，助手只在确认本目录不是磁盘根目录、不是 `C:\Windows`、
  不是 `%ProgramFiles%` 时才动手。

### 3. 批量修改最后修改日期

- 输入路径（每行一个文件或文件夹）、通配符（默认 `*`）、是否递归；
- 可以勾选「同时修改接收端自己的文件」，把安装目录加入本次范围；
- 支持固定时间 `YYYY-MM-DD HH:MM:SS`，或给出起止时间后每个文件在区间内散列取秒，
  避免整批文件时间完全一致；
- **先写记录再改文件**：`%APPDATA%\LanCmd\dates\<编号>.json` 保存设备号／inode、
  大小、原日期、写入的日期与逐项状态；
- 文件系统不能精确保存（FAT 秒级／时间取整）时自动恢复原日期并报告失败，
  不把取整结果当成功；
- 「恢复原日期」只在文件身份、大小和当前日期都等于本次写入值时才还原，
  之后被编辑或替换的文件会被跳过；
- 拒绝磁盘根目录、网络路径、系统与程序目录、符号链接／目录联接，
  单次最多 20000 个文件。

## 三、公网联机（`tunnel`）

首页「系统与应用 → 公网联机」，用 `frpc` 把公网端口映射到接收端端口。

- **配置方式**：填节点地址、端口、用户令牌、隧道名、远端端口；
  或者把 ChmlFrp 面板生成的 `frpc.ini` / `frpc.toml` 整段粘贴进来，原样使用。
- **自动选择语法**：读取 `frpc -v`，0.52 及以上生成 TOML，之前生成 INI。
- **客户端位置**：`frpc.exe` 放在接收端目录或 `frp` 子目录，也可以在设置里给出绝对路径；
  本工具不自动下载可执行文件。
- **查询节点**：调用 ChmlFrp v2 `GET https://cf-v2.uapis.cn/nodeinfo?token=…&node=…`，
  校验令牌与节点在线状态，并显示节点地址、端口和 frpc 版本。
- **守护**：输出写入 `%APPDATA%\LanCmd\tunnel.log`；异常退出按 5s、10s… 退避重启，
  连续 6 次失败后停止并保留最后一条错误；「停止」立即结束 frpc。
- **开机自动拨号**：「启用公网联机」+「接收端启动时自动拨号」同时打开时，
  接收端启动后自动建立隧道。
- 手机侧不需要改协议：在首页「手动输入电脑地址」填 `节点地址:远端端口` 即可。

> 流量经过第三方 frps，握手本身没有额外加密（协议明文 JSON + 配对 token 仅作标识）。
> 敏感环境请自建 frps，或只在需要时临时开启隧道。

## 兼容性

- 双端 3.17.0，Android versionCode 61，保留原签名与 miuix／KernelSU 外观。
- `capabilities.features` 新增 `app_control, app_control_bind, app_hidden,
  dates_batch, self_manage, self_rename, self_delete, tunnel`；
  旧接收端不报告这些能力，安卓页面会提示完整更新而不是静默降级。
- 新增模块 `app_control.py`、`dates_batch.py`、`self_manage.py`、`tunnel.py`，
  必须随整包更新；只更新 EXE 或安卓端会得到「未知命令」。
- 原有「本机维护.cmd」仍保留：它在电脑前可见、需本机确认，与本版远程维护互不替代。

## 风险与边界

- 自我删除、批量日期、窗口隐形都会产生用户难以从手机端完全撤销的后果：
  删除不可恢复，日期修改会影响文件签名与备份判断，隐形窗口占用内存。
  这些操作都需要手机端二次确认，并且不处理系统目录与程序目录。
- 批量日期只改最后修改时间，不改内容、创建时间与访问时间；
  若文件被其他程序打开，Windows 可能拒绝写入，逐项结果里会显示失败原因。
- 应用快捷控制依赖目标程序的默认快捷键；不保证在所有版本、所有输入法状态下有效。
- 公网联机依赖第三方节点可用性，节点离线或端口被占用时会明确报错。
